Escaping text for safe HTML

Characters like <, > and & have special meaning in HTML, so to show them as literal text you must replace them with entities (&lt;, &gt;, &amp;). This encodes your text so it displays exactly as written instead of being interpreted as markup.

Two big reasons to encode

  • Showing code in a page: to display an HTML example without the browser rendering it, the angle brackets have to be entities — otherwise your <div> vanishes into an actual div.
  • Safety: escaping user-supplied text before putting it in a page is a core defence against cross-site scripting (XSS). If you're inserting untrusted input into HTML, encoding it is not optional.

For the reverse, use HTML Decode. All processing is local; nothing is uploaded.

Common questions

Why would I need to escape text before putting it in HTML?

If user-provided or arbitrary text is inserted into an HTML page without escaping, characters like < and > can be interpreted as markup — at best breaking the layout, at worst creating an XSS vulnerability. Escaping neutralizes that.

Does this escape every possible character?

It escapes the five characters that matter for HTML safety: <, >, &, " and '. That covers the standard XSS-prevention case; it doesn't transliterate accented letters or emoji, which don't need escaping in HTML.

Is this a substitute for proper server-side sanitization?

For anything security-sensitive (rendering user input in a real application), use your framework's built-in escaping at the point of output — this tool is for one-off manual encoding, not a runtime security control.
